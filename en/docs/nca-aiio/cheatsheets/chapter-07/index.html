GPU 监控、故障排查与优化速查

nvidia-smi 关键命令​

命令功能考试要点
nvidia-smi基础状态概览显存、温度、功耗、利用率
nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv精确查询指标注意指标名称拼写
nvidia-smi --loop=5每 5 秒刷新--loop=N，N 为秒数
nvidia-smi -i 0仅查看 GPU 0用 -i 指定编号
nvidia-smi -r重置 GPU用于卡死的 GPU，慎用

关键指标健康阈值​

指标正常范围异常判断考试频率
GPU 利用率训练时 70-100%低于 50% 可能存在数据瓶颈高频
显存占用训练时 80-95%>95% 有 OOM 风险高频
温度60-75 °C>80 °C 触发降频有
功耗训练时接近 TDP持续满载需检查散热有

DCGM 企业监控架构​

DCGM（Data Center GPU Manager）是 NVIDIA 企业级 GPU 监控方案：

Host Engine (nv-hostengine)
  └── 节点 Agent（每节点一个）
       └── GPU 组（逻辑集合）
            └── 健康策略 / 告警规则

DCGM 关键命令​

命令作用
nv-hostengine启动 DCGM 守护进程
dcgmi discovery -l列出所有 GPU
dcgmi group -c mygroup创建 GPU 组
dcgmi health -g 1 -c检查组健康状态
dcgmi profile --start --group 1启动 Profiling
dcgmi stats -g 1 -e查看统计数据
tip

DCGM 支持 Prometheus 导出，适合多节点集群的集中监控。

常见 GPU 问题排查​

问题现象根因解决方案
CUDA 显存不足批大小过大或内存泄漏减小批大小 / 梯度检查点 / 混合精度
GPU 利用率低数据加载跟不上 GPU增加 DataLoader workers 数
温度过高 + 降频散热不足检查风扇、环境温度、功率限制
nvidia-smi 正常但 CUDA 失败驱动版本与 CUDA 不匹配升级驱动
某块 GPU 始终空闲应用逻辑跳过该 GPU检查 CUDA_VISIBLE_DEVICES

内存优化技术对比​

技术显存节省额外开销考试频率
混合精度 (FP16)~50%极小（需 Loss Scaling）高频
梯度检查点40-60%计算时间增加 20-30%高频
减小批大小线性节省训练变慢、收敛性变化总是选项
梯度累积0%（模拟更大 batch）每一步更多迭代中等
组合优化

FP16 + 梯度检查点 → 理论上批大小可增加到原来的 4 倍。

Profiling 工具选择​

工具适用场景输出形式
nvidia-smi快速查看终端指标命令行
DCGM多节点集群监控Prometheus
Nsight SystemsCPU-GPU 交互瓶颈分析时间线 GUI
Nsight Compute单个 CUDA Kernel 级优化详细 Kernel 指标
TensorBoard Profiler训练循环中的算子级分析TF/PyTorch op 时间线
定位规则

Nsight Systems 看全局；Nsight Compute 看细节；DCGM 看生产。

批大小估算公式​

最大批大小 ≈ (GPU 显存 - 模型权重 - 开销) / 单样本激活值显存
  • FP32 激活值：批大小 × 序列长度 × 隐藏维度 × 层数 × 4 字节
  • FP16 激活值：批大小 × 序列长度 × 隐藏维度 × 层数 × 2 字节

快速诊断六步法​

① GPU 是否被识别？ → nvidia-smi（无输出 = 驱动问题）
② CUDA 是否可用？ → 运行测试代码（失败 = 驱动/CUDA 不匹配）
③ 利用率偏低？ → 数据管道瓶颈，增加 workers
④ 显存过高？ → 减小 batch 或启用优化
⑤ 温度过高？ → 检查散热系统
⑥ 某 GPU 空闲？ → 应用逻辑或设备分配问题
