应试策略与高频考点速查

考试基本参数​

指标数值策略要点
总题数50预留 15 道余量给难题
时长90 分钟平均每题 1.8 分钟
及格线~70%（35/50）允许错约 15 题，不必恐慌
题型仅单选题无多选题
交付方式远程在线提前测试考试环境

域权重与题目预估​

考试域权重约多少题复习优先级
AI 基础设施40%~20最高（题量最多）
AI 基础38%~19高（量第二）
AI 平台22%~11中（不可跳过）

时间管理检查点​

完成题数应耗时状态判断
1018 分钟正常节奏
2545 分钟正好过半
4072 分钟正常（剩 18 分钟复查）
4581 分钟稍慢（仅做快速复查）

四类题型应对方法​

题型占比时间分配解题策略
情境题40%2-2.5 分钟提取硬性需求 → 排除违规项 → 应用软性偏好
服务选择30%1.5-2 分钟排除错误类别 → 按场景匹配剩余选项
配置题20%1-1.5 分钟需要记住具体数值或语法，无步骤分
概念题10%1 分钟快速作答，不确定就先标记后跳

排除法三步走（情境题）​

第 1 步：提取硬性条件

  • 混合云还是纯本地？
  • 延迟或吞吐量的硬性指标？
  • 是否需要合规认证？
  • 规模（GPU 节点数）有无要求？

第 2 步：排除不满足的选项

  • 题目需要 64 块 GPU → 单节点方案的排除
  • 需要高可用 → 无冗余的方案排除
  • 训练 GPU 做推理场景 → 选错类别的排除

第 3 步：应用软性偏好

  • 成本优化优先 → 功能相当时选更便宜的
  • 复杂度最小化 → 能托管不自管
  • 面向未来 → 选当前主流技术而非已弃用的

高频错误答案模式​

模式典型表现本质问题
过度工程无需多区域却加了多区域增加成本无收益
不计成本简单推理却选 H100便宜方案可行时不应浪费
过时方案新项目仍推荐 V100已退出产品线的技术
唯新是从只因 H100 最新就选推理场景 L40S 可能更合适

nvidia-smi 数据诊断​

观察数据问题方向
GPU 15% + 显存 95%显存瓶颈（batch 过大或数据加载慢）
GPU 98% + 显存 30%计算瓶颈（模型复杂度高或需更强 GPU）
GPU 12% + 显存 15%利用率不足（调度问题，非 GPU 本身问题）
温度 >85°C + 功率满载热降频（散热不足）
温度正常 + 功率低于 50%低利用率（轻载正常现象）

容量规划公式​

所需总容量 = 基础需求 × (1 + 冗余百分比)
所需单元数 = 所需总容量 / 单单元容量

示例：60,000 次请求/小时，开销 20%，单 GPU 处理 2,000 次请求/小时

  • 总容量：60,000 × 1.2 = 72,000
  • GPU 数量：72,000 / 2,000 = 36 块
caution

不要先算基础值再加冗余最后取整——会累积误差。每一步完整计算。

关键词解读​

题干措辞实际含义注意点
"成本效益"满足所有需求后最小化成本仍需满足所有硬性需求
"高可用"冗余 + 故障转移 + 在线 SLA≠ 灾难恢复
"可扩展"可线性增长（通常 GPU 数）可能需要多节点架构
"最小化复杂度"功能相同时优先托管/简单方案是平局打破者，非首要条件
"预算不受限"不能按成本排除选项不意味着一定要选最贵的

最后 10 分钟复查策略​

  1. 优先复查情境题和服务选择题（分值高、有套路）
  2. 用排除法：排除 2 个明显错项，正确率从 25% 跃升到 50%
  3. 策略性改答案：有依据时改，凭直觉不改
  4. 绝不空题：错答不扣分，空答一定没分

核心记忆​

  • 情境题流程：需求 → 排除 → 偏好
  • 服务选择流程：错误类别 → 错误层级 → 正解
  • 故障排查：分析题目数据，不要套练习中的模式
  • 容量计算：先乘冗余系数再除单元容量
  • 绝不假设：只基于题目明确给出的信息答题
