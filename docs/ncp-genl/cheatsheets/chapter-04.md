# RAG 与适配策略 — 速查表

## 三策略决策框架

| 策略 | 适用场景 | 不适用 |
|------|----------|--------|
| 提示词工程 | 通用能力、静态 FAQ（少量） | 私有/动态知识 |
| RAG | 动态/每日更新知识、低训练预算 | 行为/风格一致性 |
| 微调（SFT） | 严格风格/语气、稳定任务、格式遵循 | 知识频繁变化 |

## RAG 流水线组件

| 组件 | 顺序 | 功能 |
|------|------|------|
| 分块/切分器 | 1 | 将长文档切成可检索单元 |
| 嵌入模型 | 2 | 将分块转为向量 |
| 向量存储 | 3 | 索引和检索相似向量 |
| 检索器 | 4 | 初始 top-k 相似度搜索 |
| 重排序器 | 5 | 对初始结果重新打分精炼 |
| 生成 LLM | 6 | 用检索到的上下文生成答案 |

## RAG vs 微调成本/延迟权衡

| 维度 | RAG | 微调 |
|------|-----|------|
| 前期成本 | 低 | 高（GPU 训练） |
| 运行时延迟 | 增加（检索步骤） | 低（直接推理） |
| 知识更新 | 重新索引文档 | 重新训练 |
| 每查询基础设施 | 有（检索+向量库） | 无 |

## 混合策略示例

| 需求 | 最佳方案 |
|------|----------|
| 领域术语检索 | 微调嵌入模型 + RAG |
| 严格品牌语气 | SFT 微调 |
| 每日更新 + 最新知识 | RAG |
| 20 条静态 FAQ | 直接放入系统提示 |
